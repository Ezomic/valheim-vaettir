# Vaettir: the hammer is served by the chests in a jib's reach, and by nothing else (LHM-76).
#
# WHAT IT PROVES, in the order it runs. Each refusal has a positive beside it that differs in ONE
# thing, so a "no" is the feature declining and never a missing bench, an empty pack or a shut gate.
#  1. The facts the rest leans on are read off the game, not remembered: `hod cost woodwall` pins
#     the price (Wood 2, one line), and `hod build` pins the state (BuildFromChests on, the jib
#     feature not shut, no chest-building mod making the hammer step aside, the Meadows gate open).
#     A wrong guess fails HERE with a sentence, instead of failing six steps on as a number.
#  2. A chest holding wood, a pack holding none, a jib in reach: the menu's own test says yes, and a
#     real click (`build`, which presses the place button through Player.UpdatePlacement) puts the
#     wall up and takes exactly 2 wood out of the chest and none from the pack.
#  3. Pack first: one wood carried, so the pack pays 1 and the chest 1. Then two carried, so the pack
#     pays both and the chest nothing. The amounts are exact because "about right" cannot tell a
#     spend from a free build.
#  4. Out of reach: the player stands 32m from the jib, beside a bench of their own so the station is
#     not the reason. `hod build` reads scope=shut chests=0, the wall is unbuildable, and one control
#     (two wood in the pack) turns the same spot buildable, so the refusal was the scope.
#  5. Gate closed: every boss key off and the gate recomputed, jib and chest in reach, chest full.
#     `hod build` reads scope=open chests=1 gate=shut, and the wall is unbuildable. Opened again
#     afterwards, so it is the gate and not the chest that decided.
#  6. BuildFromChests off: same jib, same full chest, gate open. scope=shut, wall unbuildable; on
#     again, buildable again.
# The refused CLICK is not asserted: `build ... no` passes only when the SPOT was refused and fails
# when the refusal is want of materials, which is the case here. `buildable` is the same test the
# click makes (Player.HaveRequirements with CanBuild), and the chest count is checked unchanged.
#
# Geometry, in metres forward/right of the mark, Eikthyr down throughout:
#   bench B1   (2, -3)    jib J (-8, 0)    chest (-8, 3)    player at the mark: 8m from J
#   far bench  (26, 0)    the player stands at (24, 0), 32m from J
# Everything stays inside the 30m the stage levels.
#
# MANUAL CHECKS, which this cannot do:
#  1. Hold the Hammer near a jib with a chest of wood and nothing in your pack, open the build menu.
#     Want: the wall is not greyed, and the requirement line shows your pack count plus the chest's.
#  2. Place a wall with the mouse. Want: the build sound and the wall, and the chest is lighter.
#  3. Stand on the far side of two jibs' reach with the same chest. Want: the wall is greyed.
#  4. Another player's chest in reach (the paired scenarios cover the owner round trip).
# NOT TESTED here: the conflicting-mod switch (needs Azu Craftyboxes or similar installed; `hod build`
# prints yields=<name> when it is on, and this file pins yields=none so such a profile fails loudly),
# and the refused click for a chest owned by somebody else.

clear
give Hammer:1,Hoe:1
give FineWood:250,BronzeNails:40,IronNails:52,Chain:4,GroveHeartwood:6
give Wood:100,Stone:40
god
ghost

# The Meadows, found rather than promised, because a suite run starts wherever the scenario
# before it left you. See vaettir-jib-gate.txt.
biome Meadows
wait 3

# Cleared and levelled where `biome` left you: every piece, drop, tree and rock within thirty metres
# taken down, and the ground levelled to the height under your feet.
stage
landed
mark

# The switch on, whatever an earlier run left, and Eikthyr's key put back as a real add so the gate
# recomputes from the list as it now stands.
mod hodbuild on
unkey defeated_eikthyr
wait 1
key defeated_eikthyr
wait 2

# ---- 1. pin what is assumed
console hod cost woodwall
printed lines=1 Wood=2 end yes
console hod build
printed setting=on enabled=on shut=no yields=none yes
printed gate=open yes

# The bench the wall needs in range, the jib, and the chest. The bench is a fixture and needs no roof:
# a roof gates crafting AT a station, not building near one.
place piece_workbench 2 -3
wait 2
place hod_jib -8 0
wait 4
place piece_chest_wood -8 3
wait 3
claim piece_chest_wood
wait 1
stock piece_chest_wood Wood:20
strip Wood
wait 2

console hod build
printed scope=open chests=1 yes

# ---- 2. the chest alone pays
buildable woodwall yes
tool Hammer
build woodwall 3 0 yes
wait 2
holds piece_chest_wood Wood 18
carrying Wood 0

# ---- 3. pack first, then chest
give Wood:1
wait 1
build woodwall 3 3 yes
wait 2
carrying Wood 0
holds piece_chest_wood Wood 17

# Not at 3 -3: the workbench stands at 2 -3, a wall is two metres wide, and the first run (2026-10-07)
# could not put the ghost on the spot ("best 195cm off, last on collider"). Nothing was built, the two
# wood stayed in the pack, and the failures that followed (carrying 2, and a buildable that was only
# true because of that wood) were that one bad spot, not a double take.
give Wood:2
wait 1
build woodwall 3 -7 yes
wait 2
carrying Wood 0
holds piece_chest_wood Wood 17

# ---- 4. the player out of every jib's reach, with a bench of their own
landed
move 24 0
landed
place piece_workbench 2 0
wait 3
console hod build
printed scope=shut chests=0 yes
buildable woodwall no
give Wood:2
wait 1
buildable woodwall yes
strip Wood
wait 1
buildable woodwall no
landed
back
landed

# ---- 5. the gate closed with everything else in place. The gate recomputes on a key being ADDED and
# not on one being taken away (HodWorld patches GlobalKeyAdd only), so the keys come off and a made-up
# one goes on to make it look again.
unkey defeated_eikthyr
unkey defeated_gdking
unkey defeated_bonemass
unkey defeated_dragon
unkey defeated_goblinking
unkey defeated_queen
unkey defeated_fader
unkey hodrig_recompute
wait 1
key hodrig_recompute
wait 2
console hod build
printed scope=open chests=1 gate=shut yes
buildable woodwall no
holds piece_chest_wood Wood 17
carrying Wood 0

# Opened again, by a real add: nothing else has changed, so the gate was what said no.
key defeated_eikthyr
wait 2
console hod build
printed scope=open chests=1 gate=open yes
buildable woodwall yes

# ---- 6. the switch
mod hodbuild off
console hod build
printed setting=off yes
printed scope=shut chests=0 gate=open yes
buildable woodwall no
holds piece_chest_wood Wood 17
mod hodbuild on
console hod build
printed setting=on yes
printed scope=open chests=1 yes
buildable woodwall yes

# The mod's own state is the one thing left behind: the switch is on, Eikthyr's key is set, and the
# jib, the benches, the walls and the chest are taken down by the next scenario's stage.
landed
back
