# Vaettir: a second patch planted a few metres from the first lands on the first patch's grid.
#
# LHM-29. Robbin: "when planting crops it sometimes looks like it's using a different grid for
# a certain patch than another", and later "same grid angle but different". Two patches of one
# field, rows at the same angle, shifted against each other. The grid used to start a new
# lattice under the cursor whenever it had lost the last bed and found no plant of the same crop
# within four metres, and the second patch of a field is exactly that. Now a plant with nothing
# near it goes on one grid shared by the whole world, so two patches that never see each other
# still share their rows.
#
# So: four carrots, a step over, and four more carrots, every one of the second patch more than
# five metres from the first. That is out of the grid's reach, so nothing but the shared grid
# can line them up. Every carrot goes in with `build`: the cultivator, the ghost, Furrow's snap
# and the place button, the way a hand does it.
#
# `mod furrowtest` does only what no step can:
#   - `forget`, at the start and between the patches. The grid holds a pin and the last bed it
#     used for as long as the game runs, and only restarting the game empties that. So the
#     second patch has the ground and the shared grid to go on and nothing else, which is the
#     case that broke. It also lifts a pin you had down.
#   - `free Oak_Sapling 0 12` puts a marker oak twelve metres along the grid's columns, and
#     `face` turns you to it. From then on forward in `build` runs along the grid's columns and
#     right along its rows, and each build's note ("0.12 forward, -0.30 right of the spot") is
#     how far the grid moved that carrot, in rows. No other step knows which way the grid runs.
#
# The second patch is 7.5m right and 0.5m forward of the first, so its first aim is exactly half
# a row off the first patch's first aim both ways. A second patch that started its own lattice
# where it was aimed, as the old grid did, can therefore never line up with the first by luck.
# The aims inside a patch are 1.75m apart: never a whole number of rows, so a patch the grid
# did not move cannot read as one grid either.
#
# What passes: the first patch alone "on one grid" with 4, then both patches "on one grid" with 8.
# What a broken build reads: a second patch on rows of its own reads "on 2 grids (4 + 4)" with
# the same angle printed twice, which is the report as the console says it. A grid that is not
# running leaves every carrot where it was aimed and the first check already reads 4 grids.
#
# Needs: singleplayer, in a test world, facing anywhere. The level Meadows ground with twenty metres
# clear that this used to ask for is the `stage`'s job now. GridEnabled and GridShared on,
# GridCell 0, Sowing off - the defaults. Farming is set to 50 so any sane GridLevel is met, and put
# back at the end. Carrots are taken to step a metre, and the check fails if it prints anything
# but "rows 1m apart". The cultivator tills where each carrot is aimed, and the grid moves a carrot
# at most 0.7m, so a `build` refused with NeedCultivated means the tilling piece is smaller than
# that, not that the grid is wrong. "out of stamina" is
# the character; eat and run it again. If `build cultivate_v2` says it is not an entry on the
# cultivator, the tilling piece has another name in this version and nothing after it counts.
#
# The stage after `biome` takes down everything within thirty metres first, the world's own trees,
# rocks and wild plants for good, and levels the ground. Leaves eight carrots, the marker oak and
# the tilled ground behind; the next run plants on fresh ground of its own.

clear
give Cultivator:1,CarrotSeeds:20
skill Farming 50

# Meadows the map has not shown you yet, found rather than promised, because a suite run starts
# wherever the scenario before it left you. In the second 2.3.0 run that was the Deep North,
# inside the Queen's entrance utangard-queen-door-stays-sealed spawns, where tilling was refused
# as snow too deep. Plain `biome Meadows` answered that and missed the next case: already in the
# Meadows, it does not move you. The third run came here straight from Malmr, whose last file
# leaves a copper deposit (rock4_copper_frac) about five metres in front of where you stand, and
# `wipe` took only pieces then (since Devkit 686ff58 it takes what `put` left too). Every `build`
# in the three furrow files that ran stopped on that
# deposit ("last on Rock4_cell ... (not the ground)"), so not one sapling or crop went in and each
# `furrow check` counted only what `furrowtest free` had put down. `fresh` always moves you, to
# ground no scenario has used.
biome Meadows fresh
wait 3

# Cleared and levelled where `fresh` put you: every piece, drop, tree, rock and wild plant within
# thirty metres taken down, and the ground levelled to the height under your feet, so every `build`
# and tilling swing below aims at the same ground. Devkit's automatic stage before the first step
# ran where the file before left you, which `fresh` never is. Before the stage a wild tree or rock
# could still stand here and stop a `build`, which named it the way it named the deposit. This
# replaces the `wipe 20` that stood here: the stage takes down everything it did and more.
stage

mod furrowtest forget
mod furrowtest free Oak_Sapling 0 12
printed off any grid yes
wait 1
face Oak_Sapling 15
wait 1
tool Cultivator


# ---- the first patch: a square 1.75m on a side

# A second between tilling swings. `build` reads the height of the ground at its spot the
# moment it starts, and a swing's new ground only reaches the terrain's collider at the end of
# the frame it lands in (TerrainComp.DoOperation pokes the heightmap to rebuild in LateUpdate).
# Devkit starts the next step in that same frame, so a swing started straight after another
# aimed at the ground as it stood before that one, the ray came down past that height, and the
# step failed "could not put the placement ray on the spot". On 2026-09-28 the second swing of
# every row did, on fresh ground; on ground already tilled there was nothing to change and the
# same swings passed.
build cultivate_v2 3.4 -1.75
wait 1
build cultivate_v2 3.4 0
wait 1
build cultivate_v2 1.65 -1.75
wait 1
build cultivate_v2 1.65 0
wait 4

# Far row first. The placement ray comes down from the camera behind you, and a carrot already
# standing between it and the next spot would stop it.
build sapling_carrot 3.4 -1.75
build sapling_carrot 3.4 0
build sapling_carrot 1.65 -1.75
build sapling_carrot 1.65 0
wait 1

mod furrow check sapling_carrot 6
printed furrow check: 4 yes
printed rows 1m apart yes
printed on one grid yes
wait 3


# ---- the second patch, the same square, half a row off both ways and out of reach

mod furrowtest forget
move 0.5 7.5

build cultivate_v2 3.4 -1.75
wait 1
build cultivate_v2 3.4 0
wait 1
build cultivate_v2 1.65 -1.75
wait 1
build cultivate_v2 1.65 0
wait 4

build sapling_carrot 3.4 -1.75
build sapling_carrot 3.4 0
build sapling_carrot 1.65 -1.75
build sapling_carrot 1.65 0
wait 1

# Both patches, from where you now stand: the first is 7 to 10m away.
mod furrow check sapling_carrot 12
printed furrow check: 8 yes
printed on one grid yes

skill Farming back
