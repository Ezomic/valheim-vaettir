#! partner paired-vaettir-race-owner
# Vaettir, TWO CLIENTS - the genuinely simultaneous race.
#
# HOW TO RUN IT
#
#   Run own-profile\pair.ps1. When it says READY, press Run on THIS file in the window titled
#   "Valheim A": F6 > Scenarios > Two players > paired-vaettir-race-asker-late > Run.
#
# Its `#! partner` line starts paired-vaettir-race-owner.txt on the other client, which works for
# either variant unchanged, because its assertions never say which side won. So in this variant
# the owner runs in window B and this file in window A, the other way round from the plain race.
# Nothing in either file cares which window it is in. Pressing race-owner instead would start
# the plain paired-vaettir-race-asker.txt, since that is the partner race-owner names.
#
# This version (2026-09-30) has not been run yet.
#
# This client owns nothing. Its craft fires a withdrawal request that is in flight while the
# owner is spending out of the same chest locally, and the owner's clamp against live stock
# is the single line that decides whether this run produces one bow or two.
#
# THE TWO PAYMENTS, AND WHY THIS FILE WAITS. The withdrawal is fired from a postfix on
# OnCraftPressed, so this client's material leaves the owner's chest within a frame or two of
# pressing the button. The owner's own spend happens in DoCrafting, when its craft timer
# expires - about two seconds after ITS press. Pressing at the same moment therefore is not
# simultaneous at all: this side pays two seconds earlier and wins every time, which is what
# paired-vaettir-race-asker.txt demonstrated six runs running.
#
# Waiting for the owner's craft timer before pressing lines the two payments up instead. The
# number is the craft duration - two seconds, less up to 60% for Crafting skill, so never
# below 0.8 - and 1.8 puts this client's request into the frames around the owner's spend on
# a character with no skill. On a well-levelled one, lower it.
#
# EITHER SIDE MAY WIN and both are correct. Only two bows is wrong, and the assertions say
# nothing about who got it.
#
# It stays wherever this character is until the owner's chest is stocked, then comes over with
# `partner`. Not before, because the owner stages its ground first, and a stage can move it.

clear
give Hammer:1,Hoe:1
god
ghost
sweep

# The signals this side waits for. The owner's file starts in the same second as this one, and a
# `waitfor` on a key an abandoned run left set would return before the owner's own clearing got
# here. A key removed from a client is only gone here once the server's answer comes back, which
# is what the wait is for. The owner sets none of them until its build is standing, so this
# cannot clear a live one.
unkey rig_race_ready
unkey rig_race_go
unkey rig_a_dropped
wait 2

# Carried once so the material is known and the recipe appears in the panel, then thrown
# away. A single plank here and the craft is partly self-funded, which would let both sides
# succeed honestly and hide the thing being looked for.
give Wood:1,LeatherScraps:1
strip Wood,LeatherScraps
wait 1

waitfor rig_race_ready 300

# Beside the owner, two metres to its right and facing its way, short of the shed it built ahead
# of itself.
partner

# Walk to the bench BEFORE the race starts. A teleport is slow and would make this client
# late by seconds rather than by frames.
goto piece_workbench
wait 1
use piece_workbench
craftable Bow yes

key rig_race_set

# Held here until the owner fires. It pressed its own button as it set that key, so this is
# the owner's craft timer spent standing still, and the press after it lands where the
# owner's spend does.
waitfor rig_race_go 120
wait 1.8
craft Bow

wait 12

# Nothing is a good outcome. It means the owner won, which is one of the two right answers.
close
drop Bow
key rig_b_dropped

waitfor rig_a_dropped 120
wait 2

# One bow's worth of material, one bow. Two here is the bug.
dropped Bow 1

# This client's replica of a chest it does not own. Not authoritative - the owner asserts
# that - but a disagreement between the two is how a lost reply looks.
holds piece_chest_wood Wood 0
holds piece_chest_wood LeatherScraps 0
