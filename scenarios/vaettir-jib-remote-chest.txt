# Vaettir: a chest that is not yours, and an owner who never answers.
#
# I had written this off as impossible on one machine. It is not. Ownership is a number on
# the ZDO, and Devkit already writes it - `strand` hands the nearest chest to another peer if
# one is connected and to nobody at all otherwise, and either makes IsOwner() false. Which is
# the whole of what "somebody else's chest" means to the code.
#
# So this enters the half that early-returns in a solo world: HodWithdraw.Ask, the routed
# request, the correlation id, and the five second timeout.
#
# WHAT IT PROVES DEPENDS ON WHERE IT RUNS, and the difference matters:
#
#   Solo - the owner is nobody, the request reaches no one, no reply comes. This proves the
#   part that matters most when an owner does not answer: NOTHING IS TAKEN AND NOTHING IS
#   CONJURED. The craft declines and the chest is untouched.
#
#   On the dev server - the owner is the server, the request is answered, and the same
#   scenario is the whole round trip. Run it there and the last assertions change: the craft
#   succeeds and the chest goes down by exactly one bow.
#
# Still out of reach either way: two players crafting from one chest in the same second.
# That is a race between two machines and there is no honest way to stage it on one.
#
# Stand on flat ground with about ten metres clear, away from other posts and chests.

place piece_chest_wood 6 1

# From here it is somebody else's chest.

# Counting still works: reading a chest does not need to own it.

# ON THE DEV SERVER this is `stacks piece_chest_wood 2` with ten wood gone instead.
stacks piece_chest_wood 2
