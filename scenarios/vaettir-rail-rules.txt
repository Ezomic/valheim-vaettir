# Vaettir: which rails count, and which are just furniture.
#
# Plan steps 17 and 18. A rail feeds the post it stands beside, one rail per post, within
# UpgradeRange - and a rail that does none of those things says so when you look at it
# rather than sitting there looking identical to one that works.
#
# The hover text is the only place any of this is reported, which is why it is asserted.
#
# The `stage` after `biome` clears and levels thirty metres round you, so the flat ground, the ten
# metres clear and the distance from other posts this used to ask for are its job now. It takes
# down EVERYTHING built there, and the world's own trees and rocks for good, so run it in a test
# world and never near a real base.

clear
give Hammer:1,Hoe:1
give FineWood:250,BronzeNails:40,IronNails:52,LeatherScraps:40,GroveHeartwood:6
god
ghost

# The Meadows, found rather than promised, because a suite run starts wherever the scenario
# before it left you. On 2026-09-28 that was the Deep North, inside the Queen's entrance
# utangard-queen-door-stays-sealed spawns, and ten Vaettir files failed on the place and not
# on the mod: tilling refused as snow too deep, and the entrance's own pieces, cut through by
# `wipe`, falling and dropping copper scrap. Already in the Meadows, this does not move you.
biome Meadows
wait 3

# Cleared and levelled where `biome` left you: every piece, drop, tree and rock within thirty
# metres taken down, and the ground levelled to the height under your feet, out past the rail 12m
# away. Devkit's automatic stage before the first step ran where the file before left you, which
# is not here when `biome` moved you. It replaces the `sweep` and `wipe 16` that stood here, doing
# both over more ground.
stage

place stow_post 4 0
wait 6
grid stow_post 6x2

# One rail, in range, and TIGHT against the post - 1m out. Which rail a post is served by
# is decided by distance TO THE POST, nearest wins, so the working one has to be the one
# standing closest to it.
place stow_rail 4 1
wait 4
grid stow_post 6x4
hover stow_rail feeding

# A second rail beside the same post adds nothing, and admits it. TWO distances have to
# come out right here and only one of them is obvious:
#
#   further from the POST than the first rail (2m against 1m), or it wins the contest and
#   the redundant one is the other rail;
#   nearer to YOU than the first rail (2m against 4.1m), because `hover` reads the closest
#   piece with that name.
#
# The first version of this got the second right and the first wrong: it moved this rail
# nearer to the player and left both rails 2.05m from the post, which is a tie broken on
# instance id - so which rail called itself redundant was arbitrary, and the run where it
# picked the other one read as the rule not working at all.
place stow_rail 2 0
wait 3
hover stow_rail adds_nothing
grid stow_post 6x4

break stow_rail
wait 2

# A rail further away than UpgradeRange, which is 5m, feeds nothing at all.
place stow_rail 12 0
wait 3
grid stow_post 6x4
